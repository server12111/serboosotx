# ser boosty — SMM-бот накрутки

Реселлер-бот накрутки (подписчики/лайки/просмотры и т.д. для Telegram, Instagram,
TikTok, YouTube и ещё ~14 платформ) поверх API `icheatbot.com/api/v2`. Пользователи
пополняют внутренний баланс через CryptoBot и заказывают услуги из синхронизируемого
каталога.

Полный план архитектуры: см. `.claude/plans/graceful-tinkering-finch.md` в профиле
пользователя (или попросите пользователя, если файл недоступен) — там разобраны схема
БД, сага размещения заказа, защита от double-spend и фоновые задачи.

## Запуск

- Локально (нужны Postgres + Redis): `python run.py`
- Docker: `docker compose up -d` (сам применяет миграции перед стартом)
- Миграции вручную: `alembic upgrade head`

## Стек

aiogram 3.20+ (цветные кнопки и `icon_custom_emoji_id` требуют именно этой версии,
Bot API 9.4), SQLAlchemy 2.0 async + asyncpg + Alembic, Redis (FSM-хранилище + локи +
анти-флуд), aiohttp для внешних API.

## Ключевые решения

- **Все денежные операции — через леджер** (`balance_transactions`), `users.balance`
  лишь кэш. Списание — атомарный `UPDATE ... WHERE balance >= :amount` (см.
  `UserRepository.try_debit`), никогда read-then-write.
- **Размещение заказа — сага в 3 шага** (`bot/services/order_flow.py::place_order`):
  резерв средств → вызов апстрима вне транзакции → финализация/компенсация. Не трогать
  без понимания зачем это так — прямая транзакция вокруг сетевого вызова держала бы лок
  на строке пользователя всё время ответа апстрима.
- **Каталог никогда не удаляется** — пропавшие из апстрима услуги помечаются
  `is_active=false`, чтобы не сломать FK у исторических заказов.
- **Весь текст в боте — на русском.**
- Все денежные колонки — `NUMERIC`/`Decimal`, никогда `float`.

## Эмодзи

`bot/utils/emoji.py::pe()` оборачивает известные глифы в `<tg-emoji>` для
`parse_mode=HTML`. Отправка кастомных эмодзи в тексте требует Telegram Premium на
аккаунте, создавшем бота в BotFather (Bot API 9.4) — без Premium теги просто не
рендерятся, ошибки не будет. Требует ли того же `icon_custom_emoji_id` на кнопках —
**проверить эмпирически при первом реальном запуске и дополнить этот пункт фактом**.

Новые платформенные эмодзи нельзя выдумывать — id нужно собрать с реального клиента.
Используйте `/emojiid` (админ-хендлер `bot/handlers/admin/tools.py`): перешлите боту
сообщение с нужным кастомным эмодзи, он ответит парами глиф → id.

## Апстрим API

`icheatbot.com/api/v2`, POST JSON, ключ передаётся в теле как `key`. Точное имя
параметра для bulk-запроса статуса (`bot/services/icheatbot.py::status_bulk`) **не
подтверждено официальной документацией** — при первом реальном запуске сверить формат
ответа и, если нужно, поправить; при ошибке автоматически используется
последовательный опрос (`status_sequential`, `Semaphore(10)`).

## `.env`

См. `.env.example`. Обязательно нужны: `BOT_TOKEN`, `ICHEATBOT_API_KEY`,
